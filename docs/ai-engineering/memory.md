# Memory

> 记忆不是“把所有对话存起来”，而是有选择地保存、更新和遗忘。

一个没有记忆的系统，每次对话都从零开始：用户要重复偏好，任务中断后无法恢复，Agent 也无法从过去的失败中学习。一个“什么都记”的系统同样糟糕：过期偏好、错误结论、敏感信息和互相矛盾的事实会不断进入上下文，最后把模型带偏。

Memory 工程的核心，不是存储容量，而是策略：什么值得记，什么时候写，如何检索，冲突时听谁的，什么时候该忘。

## 本章目标

学完本章，你应该能够：

- 区分工作记忆、对话记忆和长期记忆。
- 设计记忆的写入、检索、更新和遗忘策略。
- 处理新旧记忆冲突和多租户隔离。
- 评估记忆对任务效果和隐私的真实影响。

## Memory、Context 与 RAG

Memory 保存跨轮次、跨会话的状态和知识；Context 是这一次调用模型看到的全部信息；RAG 从外部知识库检索相关内容。Memory 和 RAG 都是 Context 的来源，但最终仍要经过选择、排序和压缩，不能直接等同于 Context。

| 概念 | 作用 | 生命周期 |
| --- | --- | --- |
| Context | 本次调用模型看到的全部信息 | 单次调用 |
| Memory | 跨轮次、跨会话保存的状态和知识 | 中期或长期 |
| RAG | 从外部知识库检索相关内容 | 每次查询 |

记忆可以分成几类：工作记忆是当前任务的临时状态；对话记忆是最近几轮对话；语义记忆保存稳定事实，例如用户偏好、项目背景和领域规则；情景记忆保存过去发生的事件；程序性记忆保存“如何做”的经验，通常更适合写成工具、工作流或文档，而不是一段自然语言。

## 写入什么，如何写

不是所有信息都值得记住。写入前要问：这条信息未来会重复使用吗，它会改变系统行为吗，它是否稳定，用户是否同意保存，是否包含敏感信息，是否已经有相同或冲突的记忆。

一条记忆至少应该包含类型、内容、来源、时间、置信度、敏感级别、租户 ID 和过期时间。来源和时间让后来的人能判断它是否可信；置信度和过期时间让系统知道该不该继续依赖它。

```json
{
  "id": "mem_001",
  "type": "preference",
  "content": "用户偏好使用中文回答",
  "source": "conversation:2026-11-09",
  "confidence": 0.95,
  "created_at": "2026-11-09T10:00:00Z",
  "expires_at": null,
  "sensitivity": "low",
  "tenant_id": "user_123"
}
```

写入策略要明确：哪些信息自动写，哪些需要用户确认，哪些只保存摘要，哪些必须脱敏，哪些根本不能保存。记忆不是日志，不需要保留每一句话；它更像一份经过筛选的档案。

::: tip 不是所有信息都值得记住
一次性的任务细节、寒暄、重复确认和已经解决的中间步骤，通常不值得进入长期记忆。工作记忆任务结束后归档或丢弃；长期记忆只保留会改变未来行为的事实、偏好和决策。
:::

## 检索、冲突与遗忘

检索记忆时，要同时考虑相关性、新鲜度、置信度、重要性、隐私和冲突。不要把所有记忆都塞进上下文；先检索、排序、压缩，再注入。重要记忆可以要求用户确认，低置信度记忆不应该单独决定行为。

记忆会冲突：旧记忆说用户偏好英文，新记忆说用户要求中文。处理原则是新信息优先于旧信息，但要保留历史；明确来源和置信度；对重要事实要求用户确认；不要静默覆盖可能影响行为的记忆；支持版本和回滚。

遗忘是记忆系统的重要能力。临时偏好和短期任务状态用 TTL 到期删除；长期不用的记忆降低权重；用户有权删除自己的记忆；合规要求支持数据保留和删除；错误记忆必须能撤销。不会遗忘的系统，最终会积累大量过期、冲突和敏感信息。

::: details 小问题：Memory 和 RAG 的区别是什么？
RAG 更关注“外部文档和知识库”，Memory 更关注“关于用户、任务和过去交互的信息”。RAG 检索的是知识，Memory 检索的是状态和经验。两者都需要权限、来源和评估，但 Memory 还要额外处理写入同意、冲突和遗忘。
:::

## 隐私与安全

记忆必须按用户、租户隔离，不能因为缓存、向量索引或日志跨租户泄露。不保存密码、Token、完整身份证号等敏感信息；明确告知用户哪些信息会被记住；提供查看、修改、删除记忆的入口；检索时也做权限检查。

记忆投毒是容易被忽略的风险：不可信网页、邮件或工具结果不能直接写成长期记忆。写入前要判断来源和可信度，敏感记忆需要确认，并记录谁写入、谁读取、谁修改。

::: warning 记忆也会被投毒
如果系统把外部网页中的“用户偏好”直接写成长期记忆，攻击者就可以通过一次内容注入改变未来所有对话。记忆写入必须有来源、置信度和审核，不能把不可信内容当成事实。
:::

## 如何评估 Memory

评估记忆不能只看“记住了多少”，而要看写入准确率、检索命中率、污染率、冲突处理、过期清理、隐私合规，以及记忆是否真的提升了任务完成率。一个记了很多但经常检索错的系统，比没有记忆更糟。

还要评估记忆对上下文成本和延迟的影响。记忆越多，检索和压缩成本越高；如果记忆没有带来明显效果，就应该减少写入或缩短保留时间。

## Memory Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 写入 | 这条信息值得长期保存吗？ | 只保留会改变行为的事实 |
| 来源 | 是否记录来源、时间和置信度？ | 补元数据，拒绝不可信写入 |
| 冲突 | 新旧记忆冲突时听谁的？ | 新信息优先，保留历史并要求确认 |
| 遗忘 | 是否有 TTL 和删除入口？ | 加过期、降权和用户删除 |
| 隔离 | 是否按用户/租户隔离？ | 检索和缓存强制带租户条件 |
| 隐私 | 是否脱敏并支持用户查看？ | 最小化保存，加审计 |
| 效果 | 记忆是否提升任务完成率？ | 做 A/B 或离线评估 |

## 总结

Memory 的价值不是“记住更多”，而是“记住该记的，忘掉该忘的”：

- 工作记忆服务当前任务，长期记忆只保留会改变未来行为的信息。
- 写入要有来源、置信度、同意和过期策略；冲突要可处理。
- 隐私、隔离和防投毒是 Memory 能上线的前提。

如果只能记住一件事：不会遗忘的记忆系统，最终会变成上下文污染源。
