# 简历

> 简历不是你的经历清单，而是“为什么你值得被面试”的论证材料。

## 本章目标

学完本章，你应该能够：

- 用一页纸组织技术简历。
- 把职责改写成问题、动作和结果。
- 根据 JD 做关键词匹配。
- 避免堆技术栈、夸大和格式问题。

## 简历的目标

让招聘方在 30 秒内判断：

- 你做什么方向。
- 你的技术深度。
- 你解决过什么问题。
- 你是否匹配岗位。
- 你是否值得进一步沟通。

## 一页纸原则

- 应届/初级：1 页。
- 中级：1 页。
- 高级：1-2 页，优先 1 页。

删掉：

- 与岗位无关的课程。
- 重复的技术栈。
- 没有结果的职责描述。
- 过度设计的名词。

## 基本结构

```text
基本信息
个人简介
技能
工作/项目经历
教育
开源/写作/证书（可选）
```

### 基本信息

- 姓名。
- 电话。
- 邮箱。
- GitHub / 博客（可选）。
- 城市（可选）。

不需要：

- 身份证号。
- 婚育信息。
- 家庭住址。
- 无关照片（除非要求）。

### 个人简介

3-4 行，说明：

- 年限和方向。
- 核心能力。
- 代表成果。
- 求职方向。

示例：

> 5 年 Java 后端经验，负责订单和支付系统，主导过幂等改造和峰值 3000 QPS 的稳定性优化。近一年实践 AI 工程，完成带 RAG 和评估的研发知识库。希望转向 AI Software Engineer。

### 技能

按熟练度分组：

- 精通：Java、Spring、MySQL。
- 熟悉：Redis、MQ、RPC、Docker、K8s。
- 了解：AI 工程、RAG、Agent。

不要写“精通”除非你能经受追问。

## 工作经历

每段经历包含：

- 公司、职位、时间。
- 业务背景。
- 你的职责。
- 关键成果。

不要写：

> 负责订单系统开发。

要写：

> 负责订单结算链路，定位并修复重复扣款问题，重复扣款率从 0.3% 降到 0，P95 延迟降低 40%。

## 项目写法

### XYZ 结构

```text
通过 X（方案），做到 Y（结果），解决 Z（问题）。
```

示例：

> 通过幂等键、状态机和唯一约束，将支付回调重复扣款从每月 12 起降为 0，回调处理 P95 从 800ms 降到 200ms。

### STAR 结构

- Situation：背景。
- Task：任务。
- Action：行动。
- Result：结果。

简历上用 XYZ，面试时展开 STAR。

### 量化

可量化：

- QPS、延迟、错误率。
- 成本。
- 用户数。
- 转化率。
- 交付周期。
- 故障恢复时间。

不能量化时：

- 影响范围。
- 复杂度。
- 复用程度。
- 团队规模。

## 关键词匹配

- 仔细读 JD。
- 提取关键词。
- 用真实经历匹配。
- 不要堆不熟悉的词。

例如 JD 要求：

- Java、Spring Boot、MySQL、Redis、MQ。
- 高并发、分布式、稳定性。
- AI、RAG、Agent。

简历中要有对应证据，而不是只列关键词。

## ATS 与格式

- 单栏。
- 常见字体。
- 不用复杂表格和图标。
- PDF 提交。
- 文件名：`姓名-职位-年限.pdf`。
- 避免图片化文字。
- 时间格式统一。

## AI 技能怎么展示

不要只写：

> 熟悉 ChatGPT。

要写：

- 做过什么 AI 应用。
- 用了什么工程方法。
- 如何评估。
- 成本、延迟、安全如何处理。

示例：

> 基于 Spring AI + 向量检索构建研发知识库问答，建立 50 条评估集，将引用准确率从 62% 提升到 88%，单次成本降低 35%。

## 常见错误

- 一页塞不下，字号太小。
- 技术栈堆砌。
- 只写职责，不写结果。
- 使用“精通”但没有证据。
- 项目没有指标。
- 简历与 JD 不匹配。
- 格式花哨，ATS 解析失败。
- 错别字。
- 时间线不连续，没有解释。
- 把团队成果写成个人成果。

## 简历 Review 清单

- [ ] 30 秒内能看出方向吗？
- [ ] 是否有个人简介和求职方向？
- [ ] 技能是否分层，不夸大？
- [ ] 每段经历是否有结果？
- [ ] 项目是否用 XYZ/STAR？
- [ ] 是否有量化指标？
- [ ] 是否匹配 JD 关键词？
- [ ] 是否一页/两页以内？
- [ ] 格式是否简洁、可解析？
- [ ] 是否有错别字和重复？

## 简历 Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 方向 | 30 秒内能否看出求职方向？ | 改个人简介，前置方向 |
| 结构 | 是否有简介、技能、经历、教育？ | 按“基本信息-简介-技能-经历”重排 |
| 结果 | 每段经历是否有结果？ | 改写成“问题-动作-结果” |
| 量化 | 是否有可量化指标？ | 补 QPS、错误率、成本、用户量 |
| 匹配 | 是否匹配 JD 关键词？ | 对照 JD 调整证据 |
| 格式 | ATS 是否可解析？ | 单栏、常规字体、PDF |
| 诚实 | 是否夸大“精通”？ | 降级为熟悉/了解，或补证据 |

## 总结

简历的核心，是让人快速判断你是否值得面试：

- 一页纸说清方向、能力和代表成果。
- 每条经历都用“问题-动作-结果”，不要只写职责。
- 用真实经历匹配 JD，不堆关键词、不夸大。

如果只能记住一件事：简历不是经历清单，而是“为什么你值得被面试”的论证材料。
