# 面试

> 面试不是考试，而是让面试官相信：你能解决他们团队的问题。

## 本章目标

学完本章，你应该能够：

- 准备 1–2 分钟自我介绍和项目故事。
- 用 STAR 讲项目、冲突和失败。
- 应对编码、系统设计和 AI 工程面试。
- 用反问和复盘改进下一次面试。

## 面试流程

常见环节：

1. 简历筛选。
2. 电话/视频初筛。
3. 编码面试。
4. 项目深挖。
5. 系统设计。
6. 行为面试。
7. 交叉面/主管面。
8. HR 沟通。

AI 岗位还可能包括：

- Prompt / Context 设计。
- RAG / Agent 方案。
- 评估与安全。
- 代码审查 AI 生成代码。

## 自我介绍

模板：

```text
我是谁：年限、方向、当前职责
我做过什么：1-2 个代表项目
我的优势：技术深度、工程能力、AI 实践
为什么来这里：岗位匹配、业务兴趣
```

示例：

> 我有 5 年 Java 后端经验，主要做订单和支付系统，负责过峰值 3000 QPS 的结算链路。最近一年在项目里落地了 Spring AI + RAG 的研发知识库，建立了评估集和工具权限体系。我比较擅长把不确定的 AI 能力做成可评估、可观测的工程系统，所以希望转向 AI Software Engineer。

控制在 1-2 分钟。

## 项目追问

面试官通常会追问：

- 你负责什么？
- 为什么这样做？
- 有哪些替代方案？
- 遇到了什么问题？
- 怎么验证？
- 如果规模扩大 10 倍？
- 如果要求强一致？
- 如果重来怎么改？

准备方式：

1. 选 2-3 个代表项目。
2. 每个项目准备 3 分钟、10 分钟两个版本。
3. 画出架构图和核心流程。
4. 准备至少 3 个取舍。
5. 准备至少 2 个失败和复盘。

## 编码面试

流程：

1. 澄清输入输出和边界。
2. 举例。
3. 说思路。
4. 写代码。
5. 测试。
6. 分析复杂度。

不要：

- 不沟通直接写。
- 忽略空值、边界和异常。
- 写完不测试。
- 不分析复杂度。
- 不会时沉默。

不会时：

- 说出已知条件。
- 提出暴力解。
- 讨论优化方向。
- 询问提示。

## 系统设计

框架：

1. 澄清功能和非功能需求。
2. 估算 QPS、存储、带宽。
3. 定义 API 和数据模型。
4. 画高层架构。
5. 深入核心流程。
6. 讨论瓶颈和扩展。
7. 说明取舍和失败处理。

重点不是“组件多”，而是：

- 为什么选。
- 数据怎么流。
- 失败怎么办。
- 如何扩展。
- 如何监控。

## AI 工程面试

常见问题：

### Prompt

- 如何写一个稳定的 Prompt？
- 如何处理输出格式？
- 如何防 Prompt Injection？

### Context

- 上下文窗口有限怎么办？
- 如何选择、排序、压缩？
- 如何处理冲突信息？

### Tool Calling

- 如何设计工具 schema？
- 如何做权限、幂等和确认？
- 工具失败如何让模型处理？

### RAG

- 如何切分文档？
- 如何做混合检索和重排？
- 如何评估检索和生成？
- 如何做权限过滤？

### Agent

- Workflow 和 Agent 怎么选？
- 如何防止无限循环？
- 如何设置停止条件和预算？
- 如何做人工接管？

### Evaluation

- 如何建立评估集？
- 如何用 LLM-as-Judge？
- 如何做回归和线上评估？
- 如何平衡质量、延迟和成本？

回答时要落到：

- 具体场景。
- 方案取舍。
- 指标。
- 失败案例。
- 安全边界。

## 行为面试

常见主题：

- 最有挑战的项目。
- 与同事冲突。
- 失败经历。
- 主动承担。
- 处理模糊需求。
- 说服他人。
- 时间管理。

使用 STAR：

- Situation：背景。
- Task：任务。
- Action：行动。
- Result：结果。

不要：

- 只讲结果，不讲行动。
- 把失败归咎于别人。
- 说“没有冲突”。
- 讲太长。

## 反问环节

好问题：

- 团队当前最重要的目标是什么？
- 这个岗位前三个月最需要解决什么？
- 团队如何做 Code Review 和发布？
- AI 项目如何评估效果和成本？
- 技术决策如何产生？

避免：

- 一上来问薪资福利。
- 问官网能查到的信息。
- 问过于空泛的问题。

## 面试后

- 记录被问住的问题。
- 复盘表达不清的地方。
- 补充知识缺口。
- 更新项目故事。
- 感谢面试官。

## 常见错误

- 自我介绍太长。
- 项目讲成技术栈清单。
- 不会时沉默。
- 不澄清需求。
- 系统设计一上来画组件。
- 不讲取舍。
- 行为面试甩锅。
- 反问说“没有问题”。
- 面试后不复盘。

## 面试 Review 清单

- [ ] 自我介绍是否 1-2 分钟？
- [ ] 是否有 2-3 个代表项目？
- [ ] 每个项目能否讲清取舍和指标？
- [ ] 编码是否先澄清再写？
- [ ] 系统设计是否先需求再架构？
- [ ] AI 工程问题是否有真实案例？
- [ ] 行为问题是否用 STAR？
- [ ] 是否准备了反问？
- [ ] 是否记录了失败问题？
- [ ] 是否针对岗位调整了重点？

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 自我介绍 | 是否 1–2 分钟、有代表项目？ | 精简为年限+方向+成果 |
| 项目 | 能否讲清取舍和指标？ | 准备 3 分钟和 10 分钟版本 |

| 系统设计 | 是否先需求再架构？ | 按统一框架演练 |
| AI 工程 | 是否有真实案例？ | 准备评估、成本、安全案例 |
| 行为 | 是否用 STAR？ | 写 5 个冲突/失败/主动故事 |
| 反问 | 是否有针对性问题？ | 准备团队目标、流程、AI 评估问题 |

## 总结

面试的核心，是证明你能解决对方团队的问题：

- 项目故事讲“约束-决策-结果”，不是技术栈清单。
- 编码先澄清再写；系统设计先需求再架构。
- AI 工程要落到评估、成本、安全和真实案例。

如果只能记住一件事：面试不是复述简历，而是把你的判断力讲给对方听。
