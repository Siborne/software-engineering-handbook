# 职业成长

> 职业成长不是“学更多技术”，而是“持续解决更复杂的问题，并让价值被看见”。

## 本章目标

学完本章，你应该能够：

- 用技术深度、工程广度和职业资产描述成长。
- 判断当前阶段最该补的能力。
- 把项目、简历、面试和写作串成证据链。
- 选择下一步要读的职业页面。

## 职业成长的三层能力

| 层次 | 内容 | 证据 |
| --- | --- | --- |
| 技术深度 | Java、Spring、数据库、并发、JVM、AI 工程 | 代码、项目、排查记录 |
| 工程广度 | 系统设计、测试、CI/CD、可观测性、安全 | 架构方案、故障复盘 |
| 职业资产 | 简历、项目表达、写作、开源、影响力 | 面试表现、作品、口碑 |

只有技术深度，容易成为“只会写代码的人”；只有表达，没有深度，也无法长期立足。

## 从 Java 开发者到 AI Software Engineer

| 阶段 | 核心能力 | 典型产出 |
| --- | --- | --- |
| Java 开发者 | 语言、框架、数据库、业务开发 | 能独立完成模块 |
| 后端工程师 | 系统设计、性能、稳定性、工程实践 | 能负责服务 |
| 高级工程师 | 复杂问题拆解、架构取舍、跨团队协作 | 能主导项目 |
| AI Software Engineer | AI 应用工程、评估、上下文、工具、Agent | 能构建可靠 AI 产品 |

这不是严格的职级对应，而是能力关注点的变化。

## 能力矩阵

### 基础

- Java 语言、集合、并发、JVM。
- Spring / Spring Boot / MyBatis。
- MySQL、Redis、消息队列。
- HTTP、RPC、网络基础。

### 工程

- 代码规范与重构。
- 测试与 CI/CD。
- 日志、指标、追踪、告警。
- 安全、权限、幂等。
- 系统设计。

### AI 工程

- Prompt 与 Context Engineering。
- Tool Calling / MCP。
- RAG、Memory、Workflow、Agent。
- Evaluation、可观测性、成本控制。
- AI Coding 与研发流程。

### 软技能

- 问题拆解。
- 沟通与写作。
- 项目管理。
- 跨团队协作。
- 技术判断与取舍。

## 职业资产

### 简历

让别人快速判断你是否匹配。

### 项目

证明你能解决真实问题，而不只是会背知识。

### GitHub / 开源

展示代码质量、协作能力和持续输出。

### 技术写作

展示思考深度和表达能力。

### 人脉与口碑

让别人愿意推荐你、与你合作。

## 成长原则

### 1. 输出大于输入

读十篇文章，不如写一个项目、做一次分享、提交一个 PR。

### 2. 先深后广

先在一个方向形成竞争力，再扩展到系统设计和 AI 工程。

### 3. 用项目驱动学习

不要“学完再做”，而是“做一个需要学的项目”。

### 4. 主动获取反馈

Code Review、面试、写作评论、用户反馈，都是成长加速器。

### 5. 让工作可见

记录问题、方案、指标和复盘，而不是只留下代码。

### 6. 长期复利

持续写作、开源、总结，比短期突击更有价值。

## 常见误区

- 只学框架，不学原理。
- 只做业务，不总结方法。
- 只追求新技术，不积累深度。
- 简历堆技术栈，没有结果。
- 项目没有指标和取舍。
- 面试前才准备，平时不记录。
- 把加班当成长。
- 不重视沟通和写作。
- 频繁换方向，没有复利。

## 总结

职业成长的核心，是让能力变成可验证的资产：

- 技术深度决定你能解决多难的问题。
- 工程广度决定你能负责多大的系统。
- 项目、简历、写作和口碑，决定价值能否被看见。

如果只能记住一件事：每年问自己一次——我今年解决过什么更复杂的问题？
