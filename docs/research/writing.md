# 从结果到论文

> 论文不是实验结果的包装，而是一条从问题到证据的完整论证。

实验终于有了提升，写作却仍然卡住，是科研中很常见的阶段。主结果有了，消融也跑了，但 Introduction 写不出动机，图表无法说明方法，实验部分像在逐张解释表格。审稿人读完以后，不知道这篇论文到底解决了什么，也不知道哪个结果最关键。

问题通常不在英语表达，而在论证结构。论文需要让读者沿着“领域重要 -> 已有工作不足 -> 本文解决什么 -> 为什么可能有效 -> 证据是否支持”一路读下去。写作的任务，是把这条线显式地组织出来。

## 本章目标

学完本章，你应该能够：

- 用一句贡献陈述概括论文的问题、方法和结果。
- 先画清动机图、方法主图和结果图，再开始写长段文字。
- 按五句话原则写 Abstract，按四段结构写 Introduction。
- 让 Related Work、Methods 和 Experiments 各自承担不同的论证任务。
- 在投稿前检查引用、图表、claim 与证据是否一致。

## 先确定贡献与故事线

动笔前先写一页“论文故事线”，不要先写 Introduction。故事线至少包含四项：要解决的问题、已有方法为什么不够、本文提出的关键机制、哪个结果证明机制有效。四项必须能互相回答，否则论文会在写作时反复摇摆。

贡献陈述可以用一个固定句式检查：

```text
针对【具体问题】，本文提出【核心方法/观察/系统】，
通过【关键机制】解决【现有方法的限制】，
在【数据集或场景】上取得【可量化结果】，
并证明【结果与问题之间的因果或经验联系】。
```

如果这句话写不完整，通常说明研究还没有形成闭环。此时回到实验设计，比继续润色文字更有效。

| 论证环节 | 读者要得到的答案 | 常见失败 |
| --- | --- | --- |
| 问题 | 为什么这个问题重要且尚未解决？ | 只写领域很大，没有具体失败 |
| 方法 | 本文用什么机制解决问题？ | 只列模块，不解释为什么有效 |
| 证据 | 哪些结果支持核心 claim？ | 主结果很多，但没有一项直接回答问题 |
| 边界 | 方法在哪些情况下不成立？ | 只展示成功案例，回避失败与限制 |

## 图比文字更早

论文中的图不是排版的附属品，而是论证的一部分。开始写正文前，先把三类图想清楚：『动机图』让读者看到问题，『方法主图』让读者看到解法，『结果图』让读者看到证据。

| 图 | 要回答的问题 | 应该避免 |
| --- | --- | --- |
| 动机图 | 现有方法在哪个场景失败，本文为什么值得做？ | 只放漂亮示意图，不展示真实冲突 |
| 方法主图 | 输入如何经过各个模块变成输出？ | 模块堆叠过多，箭头没有说明数据流 |
| 结果图 | 哪个趋势或对比最能支撑核心结论？ | 只重复表格，没有突出关键差异 |

方法主图应该和 Methods 的 Overview 对齐。读者看完图，应该能说出方法的输入、输出、主要模块和模块之间的关系；再读正文时，图负责提供全局结构，文字负责解释设计动机和关键细节。

配色、字体和线条粗细要服务于可读性。不要把重点全交给颜色，也不要用过多装饰制造“复杂感”。如果一张图在灰度打印后仍然能看懂主要结构，通常说明信息层级是清楚的。

## Abstract 写贡献说明书

Abstract 不是论文简介，而是『贡献说明书』。它要在很短的篇幅内让审稿人知道：问题是什么，为什么现有方法不够，本文提出了什么，结果如何，这对领域意味着什么。

可以用五句话检查：

1. **背景**：这项任务属于什么领域，为什么重要？
2. **问题**：现有方法在哪个具体机制、场景或假设上失败？
3. **方法**：本文提出了什么核心机制，为什么它可能解决问题？
4. **结果**：在哪些数据集、Baseline 和指标上取得了什么可量化变化？
5. **意义**：结果说明了什么，对后续研究或应用有什么影响？

第二句通常最关键。只写“现有方法仍然具有挑战”没有信息量。更好的写法是指出结构性限制，例如“现有方法假设训练与推理使用同一词表，因此无法直接复用不同模型的推测解码能力”。问题越具体，方法存在的必要性越清楚。

## Introduction 与 Related Work

Introduction 是 Abstract 的扩写，但目标更明确：建立研究领域，回顾已有工作，指出尚未解决的问题，引出本文工作。可以按四段组织：

1. **研究领域**：说明问题为什么重要，读者需要的最少背景是什么。
2. **已有工作**：概括主要技术路线和代表性进展，为 gap 做铺垫。
3. **问题与空缺**：具体说明现有方法在哪种场景、假设或评价方式下不足。
4. **本文工作**：说明本文做了什么、为什么这样做、主要贡献和关键结果。

第三段决定 Introduction 是否成立。“However, this problem remains challenging”几乎不提供信息。应该回答：哪类输入会失败？哪个假设不成立？哪个能力没有被测到？哪种成本过高？哪种数据缺失？

Related Work 不是文献罗列，而是研究地图。每一段通常先概括一条技术路线，再列代表工作，然后总结共同假设和限制，最后说明本文与它的关系。可以用 Extension、Complement、Contrast、Unification 或 Re-evaluation 描述关系，不需要强行证明“我们比别人更好”。

## Methods 与 Experiments

Methods 最好采用总分结构。Overview 先说明方法要解决什么问题、由哪些模块组成、整体流程如何；Problem Formulation 定义输入、输出和符号；Method Details 再逐个模块解释设计动机、输入输出和作用；最后写训练、优化或推理流程。

公式必须被解释。公式前说明为什么需要它，公式后定义关键符号，再说明它在方法中承担什么作用。不要为了显得“数学化”加入与论证无关的公式。

Experiments 应该从 claim 反推，而不是把所有跑过的实验都放进去。常见结构包括 Experimental Setup、Main Results、Ablation Study、Analysis、Case Study 和 Efficiency Analysis。并非每篇论文都需要全部包含，但每一项都应该回答一个明确问题。

写结果时，不要只写“Table 1 shows the results”。要告诉读者应该看什么：哪一列最关键，提升出现在哪些数据集，是否与动机一致，哪些情况下没有提升。异常结果不要隐瞒，也不要轻描淡写地改写成成功；说明限制，并解释它对结论的影响。

::: warning 图表必须和 claim 对齐
如果论文声称解决的是稳健性问题，实验却只报告平均准确率，审稿人无法确认核心贡献。主结果、消融和分析要形成一个证据链，而不是各自展示一组数字。
:::

## 引用、排版与投稿前自检

参考文献需要逐条编辑，不能从 Google Scholar 或 DBLP 复制后直接使用。同一会议的名称、缩写、大小写和届数格式要统一；会议用 `@inproceedings`，期刊用 `@article`；标题中的模型名、缩写和专有名词要用花括号保护大小写。删除无关字段，检查重复条目、缺失页码和期刊卷期号。

投稿前至少做四类检查：

- **论证检查**：标题、Abstract、Introduction、贡献列表和实验结论是否在说同一件事。
- **证据检查**：每个核心 claim 是否都有对应图表或分析，是否存在没有解释的反例。
- **图表检查**：图注是否自洽，坐标轴、单位、图例和显著性说明是否完整。
- **格式检查**：引用是否统一，页面限制是否满足，匿名要求、附录和补充材料是否符合会议要求。

## 总结

论文写作可以压缩成四句话：

- 先确定贡献和故事线，再开始写段落。
- 图负责让读者看见问题和证据，文字负责解释为什么。
- Abstract、Introduction、Methods 和 Experiments 各自承担不同的论证任务。
- 每一张表、每一段文字和每一条引用，都要能追溯到论文的核心 claim。

如果只能记住一件事：读者读完 Abstract 后，应该能准确复述你解决了什么问题，以及凭什么相信你解决了。
