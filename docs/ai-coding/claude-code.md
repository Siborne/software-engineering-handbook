# Claude Code

> Claude Code 是运行在终端里的编程 Agent，能读仓库、改文件、运行命令，并通过项目规则和权限边界工作。

工具能力会随版本变化，具体命令和配置以当前官方文档为准。

Claude Code 适合理解陌生代码库、多文件修改、修复测试失败、补测试、小范围重构、生成文档和排查构建问题。它不适合模糊需求、高风险生产操作、没有测试的大规模重写和需要大量业务判断的决策。

## 本章目标

学完本章，你应该能够：

- 用 `CLAUDE.md` 描述项目规则。
- 用计划模式拆解复杂任务。
- 设置工具权限、沙箱和危险命令确认。
- 管理长任务、MCP 工具和回滚。

## 适合什么任务

| 适合 | 不适合 |
| --- | --- |
| 理解陌生代码库 | 模糊需求 |
| 多文件修改、补测试 | 高风险生产操作 |
| 小范围重构 | 没有测试的大规模重写 |
| 排查构建/测试失败 | 大量业务判断 |

## CLAUDE.md 与计划模式

项目规则通常写 `CLAUDE.md`，描述项目结构、构建和测试命令、代码风格、禁止事项、重要约定和目录说明。规则要短、可执行、随代码维护。

```markdown
# CLAUDE.md

## Commands
- test: ./gradlew test
- build: ./gradlew build

## Conventions
- Use constructor injection.
- Do not modify generated code.

## Boundaries
- Never touch `deploy/prod/`.
- Never commit secrets.
```

复杂任务先计划：需要读哪些文件、修改步骤、影响范围、测试计划和回滚方式。计划确认后再执行，避免 Agent 基于错误理解大改。

## 工具权限、长任务与 MCP

Claude Code 可能使用文件读取、文件编辑、终端命令、Git 和 MCP 工具。权限原则是默认只读、写操作确认、危险命令确认、限制网络和文件范围、生产环境禁止自动操作。

长任务要拆成阶段，每阶段有可验证产出，定期检查进度，设置预算和停止条件，用 worktree/分支隔离，失败可回滚。

MCP 可以接入数据库、工单系统、浏览器、内部 API 和文档检索。MCP 工具要有最小权限、参数校验、错误处理、审计和写操作人工确认。

::: warning 长任务最怕“看起来在进展”
Agent 可能不断读文件、改文件、跑命令，但没有真正推进目标。用结构化计划、阶段产出和停止条件判断是否在进展，而不是看它有多忙。
:::

## 验证与 Review

不要只看总结。检查 `git diff`、测试结果、构建结果、是否修改无关文件、是否引入依赖、是否泄露敏感信息。复杂任务要有测试或可复现的验证步骤。

## Claude Code Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 规则 | 是否有 `CLAUDE.md` 或等价规则？ | 补命令、约定和边界 |
| 任务 | 是否有明确范围？ | 补规格和验收 |
| 计划 | 复杂任务是否先计划？ | 先探索再修改 |
| diff | 是否只改目标文件？ | 回滚无关修改 |
| 验证 | 是否运行测试和构建？ | 失败先分析 |
| 权限 | MCP 工具是否最小权限？ | 收紧权限，加确认 |

## 总结

Claude Code 的核心，是用项目规则和计划模式管理终端 Agent：

- 规则告诉它怎么工作，计划告诉它先做什么。
- 权限、沙箱和回滚决定它能不能安全地做。
- diff、测试和构建决定结果能不能合并。

如果只能记住一件事：Agent 越自主，越需要清晰的规则、权限和验证。
