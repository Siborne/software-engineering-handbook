# Context

> AI 编程效果的上限，通常不是模型能力，而是它在正确时刻看到了哪些代码和信息。

同一个模型，只给一句“帮我修 bug”，只能猜；给出错误日志、相关文件、复现步骤和测试，能直接定位；把整个仓库塞进去，又可能被无关代码淹没。AI 看不到你脑子里的项目背景，上下文要靠你主动组织。

Context Engineering 在 AI 编程里，就是决定给什么、不给什么、以什么顺序给、给多少。

## 本章目标

学完本章，你应该能够：

- 写出可执行的仓库规则文件。
- 选择与任务相关的文件、测试和错误日志。
- 控制上下文预算并排除污染。
- 为多文件任务准备清晰的上下文。

## 代码上下文从哪里来

| 来源 | 作用 |
| --- | --- |
| 当前文件和选区 | 最直接的修改目标 |
| 打开的文件 | 相关模块和调用方 |
| 仓库规则 | 构建、测试、风格、边界 |
| 搜索结果 | 符号、调用链、相似实现 |
| 测试 | 期望行为 |
| 错误日志/堆栈 | 问题现场 |
| git diff | 本次变更范围 |
| 依赖清单 | 版本和可用 API |
| 文档/README | 业务背景和使用方式 |

优先级是：直接修改的文件、调用方和被调用方、相关测试、数据模型/接口、配置和依赖、文档。不要把 `node_modules`、构建产物、生成代码和无关模块塞进去。

## 仓库规则与文件选择

很多 AI 编程工具支持项目级指令文件，例如 `AGENTS.md`、`CLAUDE.md`、`.cursor/rules`。规则应该写项目是什么、如何安装依赖、如何运行测试、如何构建、代码风格、目录结构、不能修改的模块、危险操作和提交规范。

```markdown
# AGENTS.md

## Commands
- install: pnpm install
- test: pnpm test
- build: pnpm build

## Conventions
- TypeScript strict mode.
- Do not add dependencies without approval.

## Boundaries
- Never modify `infra/prod/`.
- Never commit secrets.
```

规则要短、可执行、和代码一起维护。太长的规则文件会被忽略，矛盾和过时的规则比没有规则更危险。

搜索时用具体问题，例如“找到处理支付回调的入口，以及它调用的幂等校验逻辑”，而不是“看看支付相关代码”。好的检索能减少无关文件进入上下文。

## 错误现场与测试

修 bug 时至少提供错误信息、堆栈、复现步骤、期望行为、实际行为、相关日志和最近变更。示例：

```text
复现：
1. 提交订单 ORD-001。
2. 支付回调重复发送两次。
3. 订单被扣款两次。

期望：同一个支付流水号只扣一次。
实际：第二次回调仍然扣款。
```

测试是最好的行为说明：现有测试说明当前行为，失败测试说明期望行为，测试命名说明业务规则。让 AI 修改代码前，先让它读测试；如果测试本身不验证行为，先补测试。

## 上下文预算与污染

上下文不是越多越好：模型窗口有限，无关信息会稀释注意力，长上下文增加延迟和成本。优先给任务和验收标准、直接相关文件、测试、错误日志，再给调用方/依赖和背景文档。

常见污染包括过期文件、生成代码、vendor/第三方代码、无关日志、错误的历史结论、包含提示注入的文档。处理方式是明确数据来源、优先最新代码、排除生成目录、截断日志、把外部内容视为数据而不是指令。

::: warning 不要把整个仓库塞给 AI
全仓库上下文不会自动带来全局理解，反而会让模型抓不住重点。先检索、选择、压缩，再组装；上下文的质量比数量更重要。
:::

多文件任务前，让 AI 列出相关文件，人确认范围，再读关键文件、制定计划、小步修改。不要让 AI 在没有读完调用链的情况下直接改多个文件。

## Context Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 规则 | 仓库规则是否清晰可执行？ | 写短规则，补命令和边界 |
| 任务 | 是否提供直接相关文件？ | 用搜索定位调用链 |
| 现场 | 是否有错误日志和复现步骤？ | 补日志、期望和实际行为 |
| 测试 | 是否提供现有/失败测试？ | 先读测试或补测试 |
| 预算 | 上下文是否控制在必要范围？ | 排除生成代码和无关模块 |
| 安全 | 是否标注不可信内容？ | 数据/指令分离，权限最小化 |

## 总结

AI 编程的上下文工程，可以压缩成三句话：

- 仓库规则要短、可执行，告诉 AI 怎么构建、测试和不要碰什么。
- 任务上下文要围绕调用链、测试和错误现场组织。
- 上下文要控制预算、排除污染，外部内容只当数据。

如果只能记住一件事：AI 答得不对时，先检查它看到了什么，而不是先换模型。
