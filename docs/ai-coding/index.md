# AI Coding

> AI 编程的核心不是“让 AI 多写代码”，而是“用更低的成本完成可验证的变更”。

AI 编程最容易制造一种错觉：代码生成得很快，所以开发也很快。真实情况是，生成只是其中一小段；理解需求、准备上下文、检查 diff、运行测试、修复回归和处理 review 才是大头。如果这些环节没跟上，AI 只是把“写得慢”变成了“改得快、错得也多”。

AI 提高的是产出速度，不是判断力。工程能力越强，越能判断生成代码值不值得保留；工程能力越弱，越容易被“看起来合理”的实现带走。

## 本章目标

学完本章，你应该能够：

- 区分补全、聊天、终端 Agent 和 IDE Agent。
- 选择适合当前任务和工作流的工具。
- 用“理解 → 计划 → 小步实现 → 验证”的流程工作。
- 识别 AI 编程的安全边界和常见错误。

## AI 编程工具的几类形态

| 形态 | 交互方式 | 适合 |
| --- | --- | --- |
| 行内补全 | 编辑器里边写边补 | 样板代码、重复模式、API 记忆 |
| 聊天助手 | 选中代码/文件提问 | 解释代码、生成测试、局部修改 |
| 终端 Agent | 在命令行执行任务 | 多文件修改、运行测试、仓库级任务 |
| IDE Agent | 在编辑器内自主编辑 | 重构、跨文件修改、调试 |
| 代码审查 | 自动 review PR | 发现明显问题、补充测试建议 |
| PR Agent | 从 issue 到补丁 | 自动化重复任务 |

不同工具不是互斥的。实际工作流通常是：补全写小段 → 聊天解释 → Agent 改多文件 → 人 review → 测试验证。

## AI 擅长与不擅长

AI 擅长生成样板代码、解释陌生代码、补充测试草稿、做局部重构、根据错误日志提出假设、在多个文件之间做机械修改。它不擅长理解未写下来的业务背景、判断架构取舍、保证生成代码正确、处理模糊需求，也不对生产副作用负责。

| AI 更擅长 | AI 不擅长 |
| --- | --- |
| 样板代码、重复模式 | 理解未写下来的业务约束 |
| 解释代码、生成测试草稿 | 判断架构取舍 |
| 局部重构、机械修改 | 保证正确性和边界 |
| 根据日志提出假设 | 对生产副作用负责 |

所以工作方式要变：人负责定义问题和验收标准，AI 负责加速实现和探索，测试和 review 负责确认结果。

## 统一工作流

```mermaid
flowchart LR
    A["理解"] --> B["计划"] --> C["小步实现"] --> D["验证"] --> E["Review"]
```

理解阶段先让 AI 解释现有代码，确认调用链、状态变化和失败路径，不要一上来就改。计划阶段让 AI 列出修改步骤，明确范围和不做什么，人确认方向。实现阶段一次只改一个逻辑单元，每步看 diff，不修改无关文件。

验证阶段编译、测试、lint、类型检查和手动检查关键路径；review 阶段检查 API 是否真实存在、边界和异常、并发、安全、测试有效性。每一步都要能回滚，而不是等 AI 改完一大片再后悔。

## 上下文与安全边界

AI 看不到你脑子里的业务背景、没写下来的约束、线上真实数据和团队隐含规范。所以需要主动提供相关文件路径、关键类和接口、现有测试、错误日志、验收标准、不能修改的范围。

安全边界包括：不把密钥、用户数据、未公开代码粘贴到不可信工具；默认只读；写操作先看 diff；危险命令需要确认；在隔离分支或 worktree 中工作；不让 Agent 直接操作生产；对生成代码做安全扫描；人承担最终合并责任。

::: warning AI 生成代码也需要 review
AI 生成的代码看起来越合理，越容易让人跳过检查。API 可能不存在，边界可能没处理，测试可能只是“能过”。它和人类代码一样需要测试、review 和回滚。
:::

## 怎么选工具

选择工具时考虑：你主要在哪里工作（IDE、终端、浏览器），任务类型（补全、问答、多文件修改、PR review），上下文能力（仓库索引、文件搜索、测试运行），权限和沙箱，团队合规，成本和延迟，以及是否支持自定义规则和 MCP。

不要只看“哪个模型最强”，要看“哪个工具最适合你的工作流”。一个能读仓库、跑测试、展示 diff 的普通 Agent，可能比一个只会聊天的强模型更有用。

## AI Coding Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 任务 | 目标、范围和验收是否明确？ | 先补规格再让 AI 动手 |
| 上下文 | 是否提供相关文件、测试和错误？ | 补最小充分上下文 |
| 工具 | 是否选对补全/聊天/Agent？ | 按任务换工具，不要一把梭 |
| 验证 | 是否运行测试、lint 和构建？ | 补验证，失败先分析 |
| 安全 | 是否限制权限和敏感信息？ | 沙箱、确认、脱敏 |
| 回滚 | 是否可安全回退？ | 用分支、worktree 和检查点 |

## 总结

AI 编程的核心，是用工程流程接住更快的产出：

- 工具只是形态，理解、计划、小步实现和验证才是主线。
- 上下文和安全边界决定 AI 能不能真正进入生产流程。
- AI 生成的代码看起来越合理，越要检查 API、边界和测试。

如果只能记住一件事：AI 可以更快地写代码，但不能替你承担代码进入主干之后的长期责任。
