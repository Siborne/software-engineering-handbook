# Cursor

> Cursor 的核心价值不是“AI 写代码”，而是把补全、编辑、问答和多文件 Agent 放进同一个 IDE 工作流。

产品功能会持续演进，具体快捷键和界面以当前版本文档为准。

Cursor 把 AI 放在编辑器里：Tab 补全、行内编辑、Chat 问答、Agent 多文件修改。它适合样板代码、局部重构、解释代码、生成测试和跨文件修改；不适合模糊需求、高风险生产操作和没有测试的大规模重写。

## 本章目标

学完本章，你应该能够：

- 区分 Tab 补全、行内编辑、Chat 和 Agent。
- 用项目规则和索引提供有效上下文。
- 控制 diff、测试和回滚。
- 配置隐私、敏感文件和团队规范。

## 主要交互

| 功能 | 用途 |
| --- | --- |
| Tab 补全 | 边写边补，适合重复模式和样板代码 |
| 行内编辑 | 选中代码后给指令，局部修改 |
| Chat | 解释代码、问问题、生成测试 |
| Agent | 多文件修改、运行命令、迭代 |
| Codebase 索引 | 让 AI 理解跨文件上下文 |

Tab 补全适合重复代码、常见模式、API 调用和测试骨架，但补全可能看似合理但 API 不存在，不要盲按 Tab。行内编辑要选中准确范围、指令具体、看 diff 再接受。

## 代码库上下文与规则

索引帮助 AI 找到相关文件，但仍然要手动提供关键文件和错误日志。大仓库要限制索引范围，忽略生成代码、vendor 和构建产物，敏感文件不要进入索引。

项目规则要描述技术栈、代码风格、构建/测试命令、目录约定、禁止修改的路径和危险操作。规则要短、具体、可执行。

## Agent、隐私与审查

Agent 模式适合多文件修改、补测试、重构和修复构建/测试失败。要求先计划、小步修改、展示 diff、运行测试、可回滚。

隐私要明确代码是否上传、保存多久，企业环境关注数据驻留；不上传密钥、`.env` 和客户数据；配置忽略规则；审查第三方扩展。

::: warning 补全的 API 可能不存在
AI 补全会生成看起来合理的调用，但库版本、方法签名或导入可能不对。关键代码不要盲接受，编译和测试才是最终验证。
:::

## Cursor Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 补全 | API 和版本是否真实存在？ | 编译验证，查文档 |
| 编辑 | 是否只改必要部分？ | 缩小选区，看 diff |
| Agent | 是否先计划、小步修改？ | 拆任务，加检查点 |
| 验证 | 是否运行测试？ | 失败先分析 |
| 隐私 | 是否排除敏感文件？ | 配置忽略规则 |
| 规则 | 是否有项目规则？ | 写短规则并维护 |

## 总结

Cursor 的核心，是把 AI 放进 IDE 的日常动作里：

- 补全要快，编辑要小，Agent 要可观察、可回滚。
- 代码库索引和项目规则决定上下文质量。
- 隐私、敏感文件和测试验证，是团队使用的前提。

如果只能记住一件事：补全和 Agent 都在加速“写”，但合并前仍然要回到“验证”。
