# Gemini CLI

> Gemini CLI 把模型能力带进终端，适合在仓库里做搜索、解释、修改和脚本化任务。

工具能力会随版本变化，具体命令和配置以当前官方文档为准。

Gemini CLI 适合大范围代码理解、跨文件搜索和总结、修复构建/测试错误、生成文档、批量机械修改，以及结合 MCP 访问外部工具。它不适合模糊需求、高风险生产操作和没有测试的大规模重写。

## 本章目标

学完本章，你应该能够：

- 判断哪些任务适合终端 Agent。
- 用大上下文理解跨模块代码和长日志。
- 通过工具和 MCP 访问外部能力。
- 设计脚本化任务的安全边界。

## 适合什么任务

| 适合 | 不适合 |
| --- | --- |
| 跨文件代码理解 | 模糊需求 |
| 分析长日志和调用链 | 高风险生产操作 |
| 修复构建/测试错误 | 没有测试的大规模重写 |
| 批量机械修改、生成文档 | 需要大量业务判断 |

## 大上下文与工具/MCP

大上下文适合阅读多个相关文件、分析长日志、理解跨模块调用链。但上下文越大，成本和延迟越高，无关信息也会稀释注意力。仍然要选择关键文件，不要把整个仓库和生成目录都塞进去。

Gemini CLI 可以通过工具/MCP 读文件、搜索、运行命令、访问数据库、查文档、调内部 API。原则是最小权限、参数校验、危险操作确认、审计和不泄露敏感信息。

## 脚本化、安全与验证

脚本化适合批量分析、生成报告、定时任务和 CI 辅助检查。脚本要可重复、输出可解析、失败可检测，不要让脚本自动执行危险操作。

安全边界包括默认只读、写操作确认、命令白名单、网络限制、文件路径限制、生产环境禁止自动操作、敏感信息脱敏。

::: details 小问题：大上下文是不是可以代替检索？
不是。大上下文能放更多信息，但成本、延迟和注意力稀释仍然存在。先检索、筛选、重排，再放进上下文，通常比“把所有文件都塞进去”更稳。
:::

## Gemini CLI Review 矩阵

| 维度 | 必须回答 | 不满足时怎么办 |
| --- | --- | --- |
| 任务 | 是否明确、可验证？ | 补规格和验收 |
| 上下文 | 是否相关且可控？ | 先检索、筛选、压缩 |
| 工具 | MCP 是否最小权限？ | 收紧权限，加确认 |
| 脚本 | 是否可重复、可检测失败？ | 加退出码和日志 |
| 安全 | 是否限制命令、网络和生产？ | 沙箱、白名单、脱敏 |
| 验证 | 是否运行测试和检查？ | 失败先分析 |

## 总结

Gemini CLI 的核心，是把大上下文和终端工具结合起来：

- 大上下文适合跨模块理解，但不能替代检索和筛选。
- 工具/MCP 扩大能力边界，也扩大攻击面。
- 脚本化和自动化必须可重复、可检测、可回滚。

如果只能记住一件事：上下文越大，越要克制；能力越强，越要限制权限。
